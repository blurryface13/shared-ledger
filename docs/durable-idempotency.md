# 账单创建的持久化幂等

2026-09-20。适用于个人账单和均摊账单创建接口。

## 协议

客户端发送 `Idempotency-Key` 请求头，16–128 位字母、数字、下划线或连字符，建议 UUID。一次用户提交生成一个键，网络超时或响应丢失时沿用；用户明确新建另一笔账单必须换键。不能根据标题、金额或时间生成该键。新前端已自动发送并保存在当前表单状态；失败重试沿用原始账单快照，修改后会要求先核对旧提交，不自动重复上传附件。关闭表单/刷新页面会丢失该状态，恢复前应核对账本；跨刷新持久队列尚未实现。令牌刷新后的请求重试保留原请求号。

范围为用户 + 账本 + 操作类型 + 请求号。同键同内容返回原 billId/message；同键不同内容报 CONFLICT。摘要为完整请求 DTO 的 SHA-256，递归排序对象属性，数组顺序保留。不同用户、账本或操作独立。每次重放先重新检查当前账本成员权限。

## 事务与并发

MySQL InnoDB 复合主键负责跨实例唯一性；INSERT ON DUPLICATE KEY UPDATE 与 SELECT FOR UPDATE 在同一事务串行化同键。账单应用服务的 REQUIRED 事务加入幂等事务，业务记录与响应一起提交或回滚。响应丢失后重试可重放；新服务实例不依赖进程内缓存。外层账本 Redis 锁保留，数据库唯一键承担同请求号的最终约束。

该基础设施使用 Spring JdbcTemplate 执行少量原子 SQL，账单持久化仍为 MyBatis-Plus，两者必须使用同一 DataSource/事务管理器。事务设置 15 秒超时；它不等于所有外部调用都有端到端截止时间。禁止在 action 中启动 REQUIRES_NEW、切换数据源或提前发消息来绕开原子性。

## 部署

已有数据库先应用 `sql/docker/mysql/migrate/20260920_durable_idempotency.sql`，全新环境由 `004-idempotency.sql` 初始化。先迁移再部署后端，最后启用客户端请求头。CORS 已允许该头。未对当前运行数据库执行迁移，也未重启当前后端。

旧客户端不发请求头时保留 Redis 30 秒防重复行为，不具备持久化保证。当前范围只覆盖两种账单创建，其他写接口尚未迁移。

记录暂不自动过期；删除会重新允许旧请求号执行。后续需明确重试期限、过期键拒绝策略、容量指标及分批归档。不声称无限期免费存储或全业务 exactly-once。不同请求号的同内容操作仍可能创建两笔，这是有意支持合法重复记账。
