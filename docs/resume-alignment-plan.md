## 本轮交付边界

成员管理目前为后端所有者通过已注册用户 ID 分配角色，尚不是用户自助邀请流程。人数偏好 `people` 不等于成员列表，不自动更改人数或共享账本成员。关联账本仍独立鉴权；编辑者不能修改账本关联。

新成员可查看共享行程与历史操作记录，移除后失去后续接口访问；已读到客户端的数据不能远程收回。当前审计记录 actor/version/action/time，不包含字段级差异或历史内容恢复。所有者显式存在 tb_trip.owner_id，不可通过成员接口转移/删除。

所有写入先锁行程行，再版本比较与更新；成员变更遵守相同锁顺序。该设计串行化单个旅行团写操作，优先保证撤销与编辑顺序清楚，不宣称单团高吞吐。版本字段仍负责拒绝过期客户端提交。操作记录与业务写入同事务。

## 测量要求

每轮保留代码版本、环境、数据规模、流量分布、错误率及延迟分位数。旧报告不能被新报告覆盖。热点查询优化与异步规划恢复作为未来重点结果，不提前写入性能百分比或 QPS。

运行外部服务的压测优先使用可控桩验证并发机制；真实供应商只做配额内小规模联调，明确区分两种结果。二级缓存需同时记录收益、内存成本和一致性代价，不为技术名强行得出正收益。
