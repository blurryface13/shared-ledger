## 目标与约束

以传统 Java 后端求职为主线，围绕共享账本、旅行规划、图片凭据与水印构建可解释的工程能力。保持 DDD 模块化单体；小程序优先设计，当前新界面仍是 Web 原型，不能宣称已完成小程序迁移。Agent 负责轻量意图识别与规划建议，核心校验、权限与事务由后端执行。水印算法等待用户提供，不虚构算法实现或性能结果。

## 下一轮建议从这里开始

1. 先核对工作区差异、运行服务及数据库版本，保留已有未提交修改。
2. 优先补齐账本并发与幂等：检查幂等键作用域、请求摘要、失败清理的持有者校验、数据库唯一约束和乐观锁；先写重复提交、并发修改及越权用例。
3. 随后改造导出可靠性：事务 Outbox、发布确认、消费者幂等、有限重试、死信与补偿扫描。当前事务提交后发送消息存在丢失窗口。
4. 按回归计划验收每个模块，再做 SQL/缓存/外部调用优化及可复现性能对比。不要一次性引入大量中间件。

## 本地运行与恢复提示

仓库根目录执行 `bash scripts/regression.sh frontend` 可运行当前前端回归；后端运行参数和隔离要求见回归计划。开发机默认 Java 可能不是 21，运行 Maven 前核对 Java 版本。

前端目录为 `fronted/travel-prototype`，历史小程序目录为 `fronted/_legacy-ledger-fronted`。本地常用端口为前端 4178、后端 8081、Redis 6379；启动前检查占用，不终止未知进程。MySQL 和 RabbitMQ 使用本地容器，恢复时先检查容器状态及测试数据库隔离情况。

Documents 目录曾出现文件同步导致的长时间读取阻塞。历史验证曾使用 `/tmp/trip-ledger-verification` 构建镜像；该路径是临时产物，不是源码来源，使用前必须确认与仓库代码一致。临时日志 `/tmp/trip-ledger-server.log`、`/tmp/trip-ledger-ui.log` 也可能失效。

高德密钥放在被忽略的 `backend/trip-ledger/deploy/dev.env`，不要复制进文档、提交或测试报告。数据库升级前核对现有表结构与迁移记录；不能把初始化脚本直接重跑到已有数据上。

## 额度与中断保护约定

每个可验收的小阶段结束时保存代码、测试结果、未完成事项和下一步。需要提交时只提交本轮明确修改的文件，不夹带其他工作区改动。

额度接近上限（例如任一窗口剩余约 15%）时，优先完成当前可安全收尾步骤并更新本文件，避免开启大规模重构；记录进行中的命令、是否仍在运行及失败原因。额度检查依赖当时可用的信息，不能保证预知突然断线，因此应持续保存，而不是临近耗尽才保存。不得自动购买额度或兑换重置。

恢复开发时先读本文件和最新提交，然后核对真实代码/测试状态；文档中的历史通过记录不能替代本轮回归。尚未完成的实现、未运行的测试和待测指标必须明确标注。
