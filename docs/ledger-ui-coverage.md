# 共享账本 UI 功能对照

2026-09-19。本轮调整独立 Web 交互样稿 `fronted/travel-prototype`，沿用一套响应式设计。原 uni-app 与 Java 服务保留，未替换、未连接；以下“可操作”均指本机演示。

## 导航与页面语义

- 三个主入口为 Itinerary、Ledger、Gallery。用户提供的双角色图左侧用于行程，右侧用于画廊，保留原账本图标。
- Ledger 内组织为明细、统计、成员、审批、结算、设置。首页先展示金额和账单，管理操作收进对应页签。
- Ledger 的立体纸张、顶部导出与弹窗均展示账本内容；可选账本汇总、个人明细，调用浏览器打印/保存 PDF。
- Ledger 助手名称为“帮我算账”，使用整数分计算余额和结算建议。Itinerary 保留规划助手；Gallery 不展示行程导出或助手。

## 旧功能与本轮覆盖

对照旧 `book-detail` 页面及 ledger、billing、settlement、export 接口核验。此表明确迁移范围，不表示服务器功能已接通。

| 旧功能 | 当前样稿 | 后续接入 |
| --- | --- | --- |
| 个人/共享账单、账单详情 | 可选择参与成员、付款人、分类、日期；查看逐人分摊 | 个人账单与共享账单分别调用原接口，支持原分摊策略 |
| 修改、删除申请 | 申请、通过、拒绝、撤回；通过后更新金额 | 待我审批、我的申请、账单历史，真实身份与版本校验 |
| 分类与统计 | 分类筛选、新增分类、分类金额、成员垫付/承担 | 编辑删除分类、服务端统计、时间范围筛选 |
| 成员、角色、邀请 | 角色演示、邀请草稿/撤回 | 候选搜索、发送/收到邀请、接受拒绝、移除、服务端权限 |
| 临时成员 | 新建、挂靠、启用/停用演示 | 改名、挂靠转移、删除、参与分摊和追偿 |
| 结算批次与收付款 | 净额建议、付款待确认、模拟收款确认/拒绝、记录 | 原结算批次、待收/待付、直接收款、追偿与历史 |
| 账本设置 | 名称、预算、演示归档、操作记录 | 多账本切换、创建/删除、封面、转让/退出 |
| 账本/个人导出 | 汇总与个人明细纸张预览、浏览器 PDF、预览记录 | 原异步导出任务、状态、下载与导出历史 |
| 账单凭据 | 进入 Gallery 私密凭据预览 | 上传、与账单绑定、鉴权、签名 URL、水印任务 |

## 演示计算约束

- 金额以整数分保存。均摊余数按选中成员顺序分配，逐人合计等于账单金额。
- 修改/删除申请保存原账单快照；审批前检查变更，已有待审申请时不重复创建。
- 待确认付款不抵扣余额；新增或批准变更会撤回旧待确认付款，避免使用过时金额。
- 已确认付款参与余额计算。为避免简化模型改写历史，样稿首次确认结算后锁定账单增删改；生产版应依照原结算批次与差额规则实现，不能照搬此限制。
- 账本导出不包含私密凭据。个人明细表示自己参与分摊的账单，当前仍展示完整分摊；真实导出字段必须由服务端权限裁剪。
- 邀请不会发送、确认付款不会真实转账、角色切换不构成服务端授权。临时成员暂不计入分摊。

接入次序：账单与权限 → 邀请/临时成员 → 审批/结算批次 → 导出/凭据。原后端的事务、幂等、并发校验与审计仍是权威边界，前端不替代。
