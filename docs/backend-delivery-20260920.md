# 账本接入与旅行后端实施记录

## 本轮结果

保留 DDD 模块化单体，使用项目现有 Java 21、Spring Boot、MyBatis、MySQL、Redis 与 RabbitMQ。新 Web 通过 `serve.py` 同源转发 API；错误显式显示，不回退演示账单。

旅行模块分为 domain/application/infrastructure/interfaces。MySQL 持久化行程与规划草稿；行程拥有者隔离、整体验证、乐观版本更新、锁定卡片和已完成卡片保护、归档恢复、可选账本关联。关联需账本管理权限，数据库唯一约束避免重复绑定。单行程限制 30 天、180 张卡、每日 12 张，适用于轻量个人规划，非无限大协作文档。

规划目前是规则驱动：查询/创建/重排意图分支，偏好筛选 POI，安排时间段，保留锁定和已完成内容，输出可审阅草稿，确认时再次检查行程版本；草稿 24 小时有效。人数、预算、节奏、住宿偏好可记录，但未实现真实房价、订单解析、预算最优化或通用 LLM Agent。

地图适配高德地点搜索和步行路线，不索取定位。Redis 缓存 15 分钟，单实例四并发外部查询与网络超时，失败明确返回；前端以路线几何绘制 SVG、站点和播放动画，未叠加地图底图。坐标来自 POI 或手动填写，使用 GCJ-02；路线图保持局部经纬比例，非测绘精度。公交/驾车、营业时间与预约约束尚未接入。

异步导出接续现有 RabbitMQ 实现，新增快照存储，分页读取全部可见账单；重复消费以数据库行锁和成功状态避免改写已生成快照。任务失败状态可以保留并重试。返回 PENDING 后前端查询状态，再预览快照并打印。

- 工作目录受云盘文件读取延迟影响，Maven 在 `/tmp/trip-ledger-verification` 的源码镜像执行；交付代码仍在仓库中。

## 启动与数据库

Java 使用 21。先启动项目现有 MySQL、Redis、RabbitMQ，按环境配置数据库账号、JWT 密钥与文件目录。Java 运行于 8081，前端执行 `python3 fronted/travel-prototype/serve.py`，访问 `http://127.0.0.1:4178`。该 Python 网关只绑定本机，用于开发，不是生产网关。

已有数据库依次应用 `sql/docker/mysql/migrate/20260607_export_async_status.sql`、`sql/docker/mysql/initdb/002-travel.sql`、`sql/docker/mysql/initdb/003-export-snapshot.sql`；先核对列是否已存在，避免重复执行 ALTER。新卷由 initdb 脚本初始化，旧卷不会自动重新执行 initdb。地图密钥通过 `TRIP_LEDGER_AMAP_KEY` 环境变量配置，禁止写入前端或提交仓库。

## 面试可解释边界与后续

| 场景 | 当前措施 | 上线仍需解决 |
| --- | --- | --- |
| 两端同时改行程 | version 条件更新、冲突拒绝 | 用户冲突比较与恢复，热点写压测 |
| 外部地图慢/限流 | Redis 缓存、单实例并发限制与单次超时 | 多实例配额、整个规划/路线总超时、熔断指标；多段路线可能超过前端等待时间 |
| 导出重投 | 行锁、状态机、持久快照 | Outbox/发布确认与补偿扫描，避免数据库提交后消息丢失 |
| 重复提交/结算竞争 | 现有 Redis 幂等与锁、数据库事务与约束 | 故障注入、锁租约边界与多节点压测 |
| 文件访问 | 鉴权读取账单凭据 | 对象存储生命周期、扫描与水印异步任务 |

下一阶段优先完成生产身份流程、导出消息可靠投递、真实地图联调与业务压测，再扩充 Agent。性能结论必须给出环境、数据规模、并发模型、P95/P99 和错误率。
