# 自动化回归与阶段验收

原则：开发前补充关键行为测试，完成一项即纳入回归；每轮验收不从零开始。尚未实现的能力标记计划，不能以跳过用例冒充通过。

## 当前入口

仓库根目录运行 `bash scripts/regression.sh frontend`：JavaScript 语法检查及金额、行程排序测试，目前共 8 项行为用例。

`bash scripts/regression.sh backend`：要求 Java 21、Maven、隔离测试 MySQL、Redis、RabbitMQ 与已迁移表结构。必须显式设置 `TRIP_LEDGER_TEST_DB_URL`、`TRIP_LEDGER_TEST_DB_USERNAME`、`TRIP_LEDGER_TEST_DB_PASSWORD`，及 `TRIP_LEDGER_TEST_ENV_CONFIRMED=1`，确认是可写测试环境；MQ/Redis 地址通过 Spring 对应环境变量配置。脚本不创建或清理数据库，不能对生产环境运行。报告在 `backend/trip-ledger/target/surefire-reports`。当前 Java 回归基线为上轮 39 项通过，本次文档整理不代表重新跑过全部后端测试。

`bash scripts/regression.sh all`：依次执行两类检查。任何失败返回非零退出码。

## 自动化矩阵

| 层次 | 已有基线 | 本阶段应新增 |
| --- | --- | --- |
| 纯规则 | 金额精度/分摊、排序与锁定保护、旅行领域规则 | 幂等请求摘要、结算边界、非法时间与跨天冲突 |
| 数据库集成 | 身份、账本、成员、审批/结算/导出、旅行版本/草稿 | 并发双写、同键冲突、回滚、唯一约束、迁移兼容 |
| 消息故障 | 导出失败后恢复、成功状态重复处理 | Outbox 提交后宕机、确认丢失、重复投递、死信恢复 |
| 缓存/外部服务 | 地图网关替身；真实高德人工联调 | 超时、限额、热点失效、缓存不可用、总截止时间 |
| UI 端到端 | 浏览器人工验证保存、刷新、排序、跨天、导出 | 建立隔离数据与稳定定位符后自动化；长按触屏另做真机验收 |
| 性能 | 暂无可声明指标 | 独立账本与热点账本分别压测；缓存命中/未命中、任务积压恢复 |

先用替身稳定覆盖外部接口故障；真实高德测试单独按需运行，避免日常回归依赖外部配额。水印算法提供后使用固定样本集，报告嵌入耗时、图像质量、提取率及失败分类。

## 每轮验收顺序

1. 记录提交版本、运行环境、数据库迁移版本、测试数据规模。
2. 执行本模块规则测试与相关集成测试。
3. 合并前执行全量已建立回归；记录新增/失败/跳过数量。
4. 涉及并发/消息时运行对应故障实验；涉及性能才运行有基线的对比压测。
5. 浏览器检查核心路径与失败反馈；小程序原生迁移后补微信开发者工具与真机验收。
6. 归档报告位置、未解决问题及复现步骤，更新交接记录。失败不得记为完成。

后续 CI 使用隔离数据库与固定版本依赖，无需真实用户账户或地图生产 Key。当前尚未新增 CI 工作流、Testcontainers 或自动 UI 测试，不将它们列为已交付能力。
