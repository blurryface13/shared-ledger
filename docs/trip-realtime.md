# 共享行程实时通知

## 协议与权限

WebSocket 端点 `/ws/trips`。建立连接后 5 秒内发送 JSON：`{"token":"访问令牌","tripId":7}`。令牌不能放 URL 或日志。仅接受 ACCESS 令牌，校验账号有效和行程访问权；同一连接不能切换订阅。返回 ready 后客户端通过 changes HTTP 接口补查；changed 只表示需补查，没有行程内容。

每次推送复查令牌、用户状态和成员权限。每 30 秒心跳并复查；移除成员事务产生通知，相关连接复查失败后关闭。校验和实际发送之间仍有并发窗口，因此通知严格不包含业务数据，读取数据必须再鉴权。

## 资源与恢复

每实例最多 256 条连接，每用户最多 4 条；单条输入最多 4096 字节，发送缓冲 8192 字节，发送时间限制 2 秒。提交后通知线程池 1–2 线程、队列 128，过载丢弃提示，数据库审计与每 15 秒前台轮询兜底。前端采用指数退避重连，最大约 30.5 秒；45 秒无消息关闭重连，后台页面关闭连接，重新前台订阅并补查。

通知使用 AFTER_COMMIT，回滚没有成功通知。数据库记录才是恢复依据，WebSocket 不承诺可靠投递或恰好一次。

## 部署要求

正式环境使用 HTTPS/WSS 同源代理，将 `/ws/trips` 转发到 Java，启用 HTTP/1.1 Upgrade 与 Connection 请求头；代理读取超时须大于心跳周期，例如 90 秒。配置 `APP_TRAVEL_WEBSOCKET_ORIGINS=https://实际前端域名`（对应 app.travel.websocket-origins），不使用任意来源通配符。微信原生端需配置 socket 合法域名，并实现相同的首帧认证与断线补查。

本地 4178 Python 代理仅支持 HTTP，因此本机浏览器直连 8081 WebSocket。浏览器正式环境使用同源端点。

## 已验证与未验证

完整 Java 回归 81 项、前端 41 项通过；真实 WebSocket 脚本验证非法令牌拒绝、订阅成功、提交后通知、HTTP 最新版本读取、移除成员断连。浏览器验证更新提示与主动读取后提示消除。

当前仅单实例内通知。多实例需要共享通知总线，例如 Redis Pub/Sub，每个实例将提示发给本实例连接；不应让竞争消费队列随机只通知一个实例。Pub/Sub 自身不持久化，仍依赖 changes 接口补查。尚未实施此广播，也未验证线上 WSS、微信真机、连接容量与慢客户端压测，不将当前常量当作测得容量。

验收脚本 scripts/trip-websocket-acceptance.cjs 使用显式配置的两个本地测试账号，创建专用行程，结束时移除成员并归档。
